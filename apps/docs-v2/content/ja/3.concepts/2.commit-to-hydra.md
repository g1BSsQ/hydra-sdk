hydra-node v2では、**`Init` の後にHeadは空のUTxOセットで直接Openになります**。開始時のcommit phaseはありません。資産はCardano Layer 1（L1）上の**incremental deposits**によってOpen状態のHeadに入り、incrementがfinalizeされるまでLayer 2（L2）で使用できません。

## Headのライフサイクルとdeposits

- `bridge.commands.init()` はHeadの初期化を要求し、`HeadIsOpen` がOpenを通知します。このeventには `utxo` フィールドがないため、snapshot UTxOの取得には `bridge.querySnapshotUtxo()` を使います。
- Depositは `Open` 状態のHeadに向けた独立したL1 transactionです。全員が同時にdepositする必要はなく、depositする人がHead participantである必要もありません。
- `bridge.commit(...)` は `POST /commit` でdeposit transactionの**draftを作成**します。署名・送信・確認・finalizeは行いません。

## Depositのライフサイクル

1. `POST /commit` は `cborHex` を含む**未署名draft**を返します。
2. 所有者がL1 transaction全体に署名し、Cardano L1へ送信してon-chainでの観測を待ちます。`bridge.submitCardanoTransaction(...)` はSDK経由の送信方法ですが、`TransactionSubmitted` は送信受付のみを示し、chain上の確定を意味しません。
3. `CommitRecorded` はL1上で観測されたdepositを示します（`pendingDeposit` がtransaction ID）。この時点ではHead内で**使用できません**。
4. `DepositActivated` はdepositが成熟し取り込み可能になったことを示します（`depositTxId`）。
5. `CommitApproved` はsnapshotでの承認を示します（`utxoToCommit`）。このeventには **`depositTxId` フィールドがありません**。
6. `CommitFinalized`（`depositTxId`）はon-chainのincrement transactionを観測した後に発生します。L2でUTxOが使用可能になったと判断できるのはこの時点です。Chain rollbackにより再観測が必要になる場合があります。

## SDK例: draft作成、外部署名、L1送信

次の例は標準WebSocket connectorと実在する `@hydra-sdk/bridge` メソッドを使用します。ウォレットが管理する未使用のL1 UTxOを `UTxOObject` として渡してください。**L1署名処理は別途実装が必要**です。`signOnL1` はcallback引数であり、SDK APIではありません。witnessのみではなく、*witness付きtransaction全体のCBOR*を返す必要があります。これは統合の骨組みであり、end-to-endで動くウォレット例ではありません。

```ts
import { HydraBridge, HydraHeadStatus, HydraHeadTag } from '@hydra-sdk/bridge'
import type { UTxOObject } from '@hydra-sdk/core'

const bridge = new HydraBridge({ url: 'ws://localhost:4001' })
bridge.events.on('onMessage', event => {
  if (event.tag === HydraHeadTag.CommitRecorded) console.log('Recorded:', event.pendingDeposit)
  if (event.tag === HydraHeadTag.DepositActivated) console.log('Activated:', event.depositTxId)
  if (event.tag === HydraHeadTag.CommitApproved) console.log('Approved head:', event.headId)
  if (event.tag === HydraHeadTag.CommitFinalized) console.log('Finalized:', event.depositTxId)
  if (event.tag === HydraHeadTag.DepositExpired) console.log('Expired:', event.depositTxId)
})
await bridge.connect()

async function depositUTxO(
  utxoToCommit: UTxOObject,
  signOnL1: (unsignedCborHex: string) => Promise<string>
) {
  if ((await bridge.headInfo()).headStatus !== HydraHeadStatus.Open) throw new Error('Head must be Open')
  const draft = await bridge.commit({ utxoToCommit })
  if (!draft) throw new Error('No deposit draft returned')
  const signedCborHex = await signOnL1(draft.cborHex)
  const result = await bridge.submitCardanoTransaction({
    type: 'Witnessed Tx ConwayEra',
    description: 'L1 incremental deposit',
    cborHex: signedCborHex
  })
  if (result?.tag !== 'TransactionSubmitted') throw new Error('L1 submission not accepted')
  return result
}
```

::warning
`bridge.commit()` または `TransactionSubmitted` の返り値だけでdeposit完了と判断しないでください。対応するtransaction IDをL1上で追跡し、`CommitFinalized` を待ちます。接続障害やnodeの同期問題によってevent streamが途切れることがあります。
::

## Request形式と実際の制限

- **Simple request:** `bridge.commit({ utxoToCommit })` は指定したUTxO全体をdepositします。SDK型は `SimpleCommitBody` です。
- **Blueprint request:** `bridge.commit({ blueprintTx, utxo, changeAddress })` は `Transaction` envelopeの `blueprintTx`、`UTxOObject` の `utxo`、任意の `changeAddress` を取ります。OutputでHeadに入れる資産を指定し、change addressがあればnodeが残額を調整してL1へ返します。指定がない場合、outputを持つblueprintは事前にbalance済みでなければなりません。
- 使用可能なShelley以降のUTxO（Byron addressは不可）、必要な署名鍵またはscript witness、十分なL1 feeとdeposit output用のminimum ADA、正しいchain/network情報が必要です。
- Depositはledgerのtransaction sizeとserialized output value sizeの制限を満たす必要があり、大きすぎる場合 `DepositTooLarge` で失敗することがあります。Deposit額は入力の価値を超えられません。Blueprintにstake pool/DRep登録・delegation certificateを含めないでください。
- DepositしたUTxOのreference scriptは**L2で保持されません**。アプリのscript/datum動作を確認してください。Activationとrecoveryのdeadlineはnode/protocol設定に依存し、固定のSDK timeoutではありません。
- `bridge.syncedStatus` を確認してください。`CatchingUp` のnodeはclient inputを拒否する場合があります。**Connectorの注意点:** `HexcoreConnector.commit` にはblueprint用 `TODO` が残り、gateway固有のpayloadを使用しています。上記blueprint requestがそこで動くとは限りません。

## 期限切れDepositとrecovery

Deadlineまでにincrementされなかったdepositについて、`DepositExpired` は `depositTxId` を通知します。On-chain deadline後に `await bridge.recoverDeposit(depositTxId)` を呼ぶと、L1での回収（`DELETE /commits/{txId}`）を要求できます。これは資産を**L2へ追加しません**。HeadのCloseやfanout後も未回収depositは回収可能です。資産が戻ったと判断する前にL1でrecoveryを確認してください。

`await bridge.pendingDeposits()` は `GET /commits` を呼び、UTxO objectではなく**transaction ID文字列**を返します。Custom connectorがHTTP recoveryを実装していない場合、SDKはWebSocket `Recover` コマンドにfallbackすることがあり、その場合HTTP結果は返りません。
